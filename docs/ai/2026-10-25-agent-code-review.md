# 子 agent 代码审查（2026-10-25）

两个子 agent 写的代码（`e894ab1` 底部转写/录音按钮，`304cc57` 和 `2162c2e` 开会、加入、检测会议）合并时没有逐行审，所以另开一个 agent 专门审查，结果逐条核实后修复。

**链接安全：没有问题。** 渲染进程选不了要打开的地址；白名单挡住了仿冒域名、账号密码、端口、结尾的点、punycode、编码绕过和路径穿越。另外给统一的打开函数加了一道检查：只允许 `https` 和系统设置链接。

| 发现 | 修法 |
| --- | --- |
| 中：一分钟内两次短暂用麦克风（如两次听写）就会提示"检测到会议" | 只按当前这一段连续使用计时 |
| 中：连点"发起会议"/"加入并录音"会开两个会议、建重复笔记 | 按钮在处理中时禁用；同一个日历事件只建一条笔记（主进程保证） |
| 中：点通知中心里旧的检测通知，会录进错误的笔记或建空笔记 | 每次会议有编号，只有同一场会议还在进行时才录音；已在录音时只显示那条笔记；开始录音后关掉检测通知 |
| 中低：录着 A 时点 B 的提醒，会加入 B 的会议但 B 的声音录进 A | 提醒文字写明"点击保存 A，然后加入并录制这场会议"；点击后先停掉并保存 A，再录 B |
| 低：助手崩溃后检测状态卡在"在用" | 助手退出时重置 |
| 低：冒烟测试会对真实会议弹通知 | 没有假助手的测试运行不做检测 |
| 低：重新转写进行中时"发起会议"会开会议、建笔记但录不了 | 开会和加入都先检查 |
| 低：麦克风轮询和录音在同一个线程 | 放到后台任务读取 |
| 低：一整天的"专注时间"会吞掉临时会议 | 只认带会议链接或参会人的日历事件 |
| 低：几天后的会议也显示"加入并录音" | 只在会议快开始或进行中时显示 |
| 低：关掉提醒后，检测用的日历不再刷新；未点的通知一直留在内存；"录音 N"把没存下音频的失败也算进去 | 都已修 |

没改的：间隔不到 90 秒的两场临时会议，第二场不会提示（日历会议有提醒兜底；缩短间隔会让同一场会议里的静音被当成新会议）。Zoom 链接的路径规则可以收得更紧，但主机名已限定为 Zoom 自己的域名，打开的只会是 Zoom 的页面。

测试：新增 3 个单元测试和 1 个主进程测试，都在旧代码上失败、新代码上通过。单元测试 155 个，E2E 7 组，全部通过。
